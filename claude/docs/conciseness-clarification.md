# Conciseness Clarification

"Be extremely concise" applies to **communication**, not code. Code is read far more than written — clarity and correctness first, brevity second. Never sacrifice immutability, type safety, or readability to shorten code.

## Domain rules

| Domain              | Conciseness Rule                                   |
| ------------------- | -------------------------------------------------- |
| **Communication**   | Extremely concise, sacrifice grammar               |
| **Commit Messages** | Brief, skip articles/pronouns                      |
| **Code**            | Clear and correct first, brevity second            |
| **Documentation**   | Progressive disclosure, value-first, but thorough  |
| **Error Messages**  | Concise but actionable                             |
| **Comments**        | None (code should be self-documenting)             |
| **Function Names**  | Descriptive, not abbreviated                       |
| **Variable Names**  | Clear intent, avoid single letters (except i, idx) |
